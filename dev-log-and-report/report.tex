\begin{abstract}
This paper presents MemoLang, an interpreter design project focused on building an interpreter with LLVM as a backend, optimized for matrix multiplication (with integrated CuBLAS matrix multiplication combined with a destructive-read design). The language design wants to acomplish a streamlined building process, calling into the CuBLAS Library for GPU-optimized routines.
\end{abstract}

\begin{IEEEkeywords}
matrix multiplication, LLVM, destructive-read, memory efficient, Python-like syntax, C++, CuBLAS
\end{IEEEkeywords}

\section{Introduction}

Matrix multiplication is one of the main operations used in modern computing. It appears in graphics, signal processing, scientific computing, and machine learning. In neural networks and transformer models, a large share of the computation reduces to repeated multiply-and-accumulate operations. A fast and memory-efficient matrix multiplication implementation is therefore valuable.

The goal of this project is to build a programming language that integrates CuBLAS's optimized matrix multiplication routines with a destructive-read design, in order to experiment with memory optimization and speed up matrix multiplication operations at the language level rather than only at the library level.

As datasets grow larger and models become more complex, the efficiency of matrix multiplication increasingly affects overall performance. By leveraging CuBLAS's optimized routines and incorporating a destructive-read design, this project aims to:

\begin{itemize}
\item Improve performance for matrix multiplication operations, supporting faster training and inference for machine learning models.
\item Lower the hardware-specification entry barrier for developers implementing machine learning algorithms and LLM-related code, by providing a high-level language that abstracts away low-level optimization details.
\item Improve memory efficiency, allowing larger datasets and models to be processed without running into memory constraints.
\end{itemize}

This project was inspired by the Sere programming language, the CuBLAS library, and the Clean compiler.

Matrix multiplication can be written as

\begin{equation}
C_{i,j} = \sum_{k=0}^{N-1} A_{i,k}B_{k,j}
\end{equation}

Each value in the output matrix $C$ is produced by multiplying one row of $A$ with one column of $B$ and summing the products. Efficient implementations must manage data movement, memory reuse, and (in a destructive-read scheme) the lifetime of operand buffers once they are consumed.

For this milestone, the target was:

\begin{itemize}
\item Define MemoLang's core syntax (Python-like, C++-influenced) and its destructive-read semantics.
\item Implement a lexer, parser, and AST (\texttt{ExprAST}) for the language.
\item Generate LLVM IR from the AST for arithmetic and matrix operations.
\item Integrate calls into CuBLAS for matrix multiplication.
\item Verify correctness of generated code against reference NumPy/CuBLAS results.
\item Benchmark memory usage and runtime against a naive (non-destructive-read) baseline.
\item Save logs, test results, and build artifacts as evidence.
\end{itemize}
